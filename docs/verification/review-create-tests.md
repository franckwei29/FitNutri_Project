`prepareSubmission` emits input fields only. Provider synchronously locks and clones/freezes the exact request before transport; repeated confirmation cannot send a second request. `useSubmitDraft` handles known rejection, unknown outcome, matching minimal proof and post-save refresh separately. It validates kind, submission ID, exact distinct client/record identities, dates and creation versions before clearing the draft. Unknown outcomes retain the original frozen request; receipt 404 retains that state and explicitly warns that the first request may still run. Retry sends the same request. Owner/epoch changes suppress late results and cache work. Once acknowledged, a failed refresh retains saved state and offers GET-only retry. Corrections are explicitly refused by the create builder, rather than accidentally creating duplicates.

Recovery boundary: the frozen payload is memory-only, protected by navigation/beforeunload warnings. No full record, credential or health data is written to local/session storage. Optional minimal refresh journal is not implemented in this package; hard reload loses the local request, and recovery then requires checking server History. Cross-device draft recovery is not claimed.
