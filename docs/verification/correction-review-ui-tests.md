Create and correction Review dispatch POST and versioned PUT separately. No nutrient, source override, new client identity or creation submission is added to PUT.

The user explicitly reads/compares the latest snapshot; replacing the correction with it requires a second discard confirmation and does not automatically repeat PUT. PUT retains its expected version after a known rejected calculation. Creation instead generates a new submission ID after explicit re-review, keeping the same client-entry identity. Unknown outcomes retain their original ID/payload/version; exercise views display the originally reviewed basis rather than silently switching to a newly fetched weight. Reviewed-basis metadata is copied/frozen in memory and never included in the writable API payload or browser storage.
