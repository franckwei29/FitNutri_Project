# B00/B02 — Runtime persistence and privacy hardening (BC-13)

Reason: F18's actual local restart exposed Open-in-View enabled by default while integration-test properties disabled it. The original default error-message policy was also always, and ORM constraint logging could include SQL/failing rows. These are corrected explicitly as a backend package, not hidden in the frontend F18 change.

Changes: application.properties disables Open-in-View for all API runtimes and makes default container message/stacktrace/binding details never. Removed the integration profile's duplicate Open-in-View override, so real HTTP tests now inherit the SAME main policy. Suppress only Hibernate's raw JDBC error-detail loggers; application request diagnostics remain enabled. No schema/migration/record/role change or disabled permission checks.

RequestCorrelation generates one server UUID per request, ignores client IDs, and is shared by ApiError and the outer RequestAuditFilter. The response adds X-Request-Id (documented optional response header in OpenAPI, no JSON shape changes). The filter records requestId, HTTP method plus framework route TEMPLATE, status and elapsed milliseconds. It never reads/logs body, query, identity, cookies, authorization/CSRF headers, exception messages or response/provider content. Unknown/untrusted route metadata becomes a fixed API operation, and escaped failures get status500 while propagating. Header/error correlation also covers security rejection before MVC.
