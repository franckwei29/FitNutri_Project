Implemented qa/QaRequest,QaEligibilityService,QaScopePolicy,QaContextBuilder. QaRequest matches frozen message/nullable recordRange/zone, rejects unknown top-level/nested owner/eligibility/model authority fields, bounds message2000 and requires both date endpoints when a range exists. QaEligibilityService reads current active USER and ProfileService completed adult setup in its own short REQUIRES_NEW/READ_COMMITTED transaction every time. It ignores stored aiQaEligible cache and returns QA_RESTRICTED403 for missing setup or current non-NO/missing consent. It returns normal401/403 for missing/disabled/admin identity. No profile entity leaves this service and no provider call holds this transaction. A08 must invoke it before generic feature configuration errors and again before external dispatch/output.

QaScopePolicy is an initial conservative rule layer, explicitly not an exhaustive medical, privacy or injection detector. It bounds/control-checks text, checks normalized Unicode/format characters/whitespace, distinguishes general questions vs explicitly selected recorded summaries, and refuses known medical/drug/diagnosis/treatment, individualized diet/training prescription, obvious permission/tool overrides, other-account/secret/identifier requests. Recognizable own-record questions without a selected range receive an explicit choose-range refusal instead of invented records. Static refusal explanations are boundaries, not model health advice/fallback success. Allowed questions still require restricted provider instructions and output validation in A08. Unknown language/obfuscation/semantic medical requests are not claimed solved by regexes.

QaContextBuilder validates valid zone/date and inclusive1..31day range before querying SummaryService for the server-selected owner; null range performs no record query. It deliberately constructs new typed records rather than serializing Profile, PeriodSummary, arbitrary facts maps or persistence entities. External whitelist is schema version/date range/calendar days, per-day and total recorded intake/protein/fat/carbohydrate/activity-energy metrics with known/missing/legacy coverage, activity minutes/counts, optional current explicit target comparison and fixed data-limit notices. Dates are strings and physical units are in field names. No food/activity name, raw weight/change, birth year, identity/email/ID, health answer, consent or credential is forwarded. Current target is marked present reference only; missing/unrecorded values remain NULL rather than invented zero. SummaryService may internally read its own recorded comparison/weight facts; those entire structures and prior-range facts are not sent.
