# A00 — Shared provider transport and configuration boundary

Branch develop/yuankang-wei. BC-15/BC-16 incremental Java change, no database migration/write, microservice or framework upgrade. This is transport implementation with controlled-provider tests, not live-model verification. Image, transcription, parsing and Q&A business adapters follow separately; registering the transport alone does not enable any feature.

AiProviderConfig supplies one reusable Java HttpClient (connect10s default, redirectsNEVER, managed close) and a full-response processing deadline60s default. AI_CONNECT_TIMEOUT_MS supports100–30000ms; AI_PROCESSING_TIMEOUT_MS100–180000ms, including both headers and body. These are configured resource limits, not measured end-to-end performance. OPENAI_BASE_URL is backend-only, defaults https://api.openai.com/v1/, requires HTTPS/port443 or default, exact/v1/path and no embedded credentials/query/fragment. Only a trusted server operator can change this destination; neither requests nor model output select it. The package-private loopback URI seam is for controlled test fixtures only and not an environment-configurable HTTP escape.

AiTransport.sendJson accepts only server-built input/instructions/text/max_output_tokens. It rejects model/tools/conversation/previous-response fields, requires a strict named object JSON schema, caps output tokens64–4096, and sets model from the per-feature environment configuration, store=false and stream=false. It calls the Responses endpoint. sendMultipart only accepts TRANSCRIPTION, uses actual binary bytes/generated safe filenames, per-feature model and response_format=json at audio/transcriptions. Transport audio limit8MiB; JSON request12MiB; response512KiB with a cancelling body subscriber and bounded JSON nesting/string/number lengths. Feature-specific file signatures/duration/schema/content validation remain A01/A03/A04/A08, not claimed done by this boundary.

Before any network call, validateProviderConfiguration requires enabled flag and safe nonempty backend key/model configuration and refuses an active Spring database transaction. The thread-transaction test explicitly simulates the active flag; it is not labeled a real PostgreSQL transaction test. No automatic provider retry, DB tool, external model-selected URL fetch, raw body/header/credential logging or persisted media introduced. Response.toString includes only a validated provider request ID, never output content. Adapters treat json() as untrusted and will validate refusals/incomplete output and business values before exposing a canonical DTO.

AiExceptionMapper exposes fixed safe errors without raw provider content/exception causes: upstream401/403→local503 FEATURE_NOT_CONFIGURED (not user-session401);429→RATE_LIMITED429;other errors/redirect/malformed/unusable response→502 PROVIDER_BAD_RESPONSE; full processing timeout→504 PROVIDER_TIMEOUT. A RateLimitedException carries only numeric1–300seconds Retry-After (default30 for absent/unsupported/oversized metadata). ApiExceptionHandler returns this optional header with canonical no-store ApiError. OpenAPI Error429 documents the additive header;58generated TS/Zod schemas unchanged. The UI must not continuously retry model calls.
