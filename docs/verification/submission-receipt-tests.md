SubmissionService owns the outer TransactionTemplate and returns only after commit. It locks/rechecks active USER, finds existing receipt before any new reference/date/profile/weight dependency validation, returns immutable original proof on matching replay, or conflicts409 for changed hash/kind. New submissions insert a transaction-private pending row, reject duplicate/reused client IDs across both record kinds (including soft-deleted rows), run the callback in the same transaction, verify complete identity proof, and flush final minimal JSON/committedAt. Work/flush/JSON/proof/commit failure rolls everything back. An existing outer transaction is rejected to prevent returning an uncommitted success. No external model calls belong in callbacks. Receipt JSON contains only record id/clientEntryId/date/versionAtCreation, never health, input blobs or context.

It is not authority to mint a new submission. Creation proof survives record edit/delete and replay does not recompute or resurrect. Current-record APIs must be used to inspect later state.
